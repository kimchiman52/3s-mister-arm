# Rollback-determinism harness allowlist.
#
# Symbols listed here are EXPECTED to differ between a baseline run and a
# rollback run, for a verified benign reason stated on the entry. The
# driver never silently ignores anything: allowlisted hits are still
# printed (verdict ALLOWED, with the reason) — they just don't fail the
# run. Format: fnmatch pattern, optional `# reason` (reason mandatory by
# convention; review rejects reasonless entries).
#
# Rule of thumb: an entry belongs here only if the divergence is (a) an
# artifact of the harness/diagnostics themselves, or (b) state that is
# demonstrably write-only fan-out from the simulation (sound/render
# request sinks) whose divergence cannot feed back into gameplay. When in
# doubt, leave it OUT and let the run fail — a catalogued finding beats a
# hidden one. See docs/rollback-determinism-harness.md ("Reading the
# output").
#
# "Demonstrably" means a READ TRACE, not a category. Naming a symbol's
# subsystem is not evidence that it is write-only: that argument has now been
# caught wrong five times in this tree — spmv_ng_save (exonerated as dead code
# on the wrong character enum), ldreq_result and cseSysWork and mts_ok (each
# filed as an output sink while gating saved state), and ColorRAM (a palette
# buffer that really is a palette buffer, and still fed saved frw[] bytes).
# So an entry must say which reads exist and where each one lands. Reasons on
# the §A-derived blocks below were re-derived against the code on 2026-08-30;
# three of the sixteen failed. If you add an entry, trace its reads first.

# --- loader / RAM-allocator state perturbed by speculative asset requests --
# The speculative legs re-issue load/alloc requests the restore cannot
# rewind (queue state is deliberately outside GameState). Real netplay
# rollbacks perturb these identically.
#
# CORRECTION 2026-08-24 (task #60). This block used to end with "they are
# consumed by the loader, not read by the simulation". That is FALSE for
# ldreq_result and it is the reason this block hides a real desync class:
#
#   ldreq_result is read by Check_LDREQ_Queue_Player / _Union / _Direct
#   (io/gd3rd.c), which gate Exit_6th (screen/sel_pl.c:1701-1722 -> Exit_No,
#   Exit_Timer) and Bonus_Sub's stage wait (game.c:1377-1381 -> G_No, G_Timer).
#   Exit_No/Exit_Timer/G_No/G_Timer are ALL in the rollback save set
#   (netplay/game_state.c:456/607/453/540). Saved state is therefore derived
#   from an allowlisted, unsaved symbol -- the textbook DIVERGENT+FEEDBACK
#   shape, which this allowlist entry suppresses by construction.
#
# These entries stay, because the divergence is not fixable by save-set
# membership: afs_handle is an index into port/io/afs.c's requests[] table
# whose SDL_AsyncIO* and read cursor cannot be rewound, and AFS_Read is a
# real async disk read (afs.c:366), so completion timing is wall-clock, not
# frame-count. The empirical proof is in this harness's own output: q_ldreq,
# rckey_work, rckey_mmobj, texgrplds, char_init_data, requests and afs all
# appear in the A1-vs-A2 BASELINE NOISE list -- they differ between two
# identical no-rollback runs of the same binary on the same machine. Two peers
# cannot agree on them either, and no local save/replay scheme changes that.
# The correct treatment is a load barrier (keep the simulation from observing
# an in-flight LDREQ load while a session is running), not a wider save set.
#
# CORRECTION 2026-08-25 (task #65): asyncio_queue used to be named in that
# list and no longer belongs in it. It is a whole-pointer static
# (SDL_AsyncIOQueue*, port/io/afs.c:47), so it is now pointer-canonicalized in
# the capture and holds one identical hash in every run. Its former noise
# membership was evidence of ALLOCATOR nondeterminism -- it only ever carried
# the queue's address, never its contents -- not of loader timing. The genuinely
# wall-clock members above are unaffected and still noise-masked, so nothing
# about this block's conclusion changes.
#
# UPDATE 2026-08-24 (task #66): that barrier now exists. Check_LDREQ_Queue()
# (io/gd3rd.c) finishes every queued request inside the simulated frame that
# pumped it whenever Ldreq_BarrierActive() -- i.e. whenever the GekkoNet
# session is RUNNING. The queue is therefore empty and afs_handle is AFS_NONE
# at every simulated-frame boundary IN NETPLAY, which makes ldreq_result a
# pure function of the Push_LDREQ_Queue_* sequence (driven by SP_No/G_No/
# bg_w.stage, all saved).
#
# These entries still stay, and this harness's verdict is unchanged, because
# the barrier is deliberately netplay-gated: an rbd run has no session and no
# --ldreq-barrier-force, so it takes the stock unbarriered path and these
# symbols keep behaving exactly as described above. The barrier is validated
# by tools/ldreq-timing (which varies loader wall-clock rather than rollback
# cadence) -- see known limit 9 in docs/rollback-determinism-harness.md for
# why this harness cannot do that job.

# Do NOT quietly widen this block. Candidate_Buff still diverges at

#
# UPDATE 2026-08-25 (task #69): plt_req IS now allowlisted, below, and it is
